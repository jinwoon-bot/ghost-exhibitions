# 야광귀 — 하나, 둘, 셋…

## 작품

설밤에 신발을 가져가는 야광귀를 막기 위해 대문이나 장대에 체를 걸어두었다는 믿음이 전해집니다. 야광귀가 구멍을 세다 틀려 날이 샐 때까지 다시 센다는 이야기입니다. 전시에서 박수가 수를 끊는 방식, 체 구멍의 눈, 마지막 속삭임은 이 이야기를 바탕으로 창작한 연출입니다. [국립민속박물관 〈야광귀〉](https://www.nfm.go.kr/kids/elecontents/view.do?topic=10) · [한국민족문화대백과사전 〈야광이 쫓기〉](https://encykorea.aks.ac.kr/Article/E0035251)

- 첫 박수에 숫자 세기가 멈추고, 마른 체 소리와 함께 망 뒤의 눈 하나가 뜹니다. 짧은 틈 뒤 ‘하나’부터 다시 셉니다.
- 기본 설정에서 18초 안에 박수가 이어지면 눈이 1개, 4개, 9개, 16개로 늘어납니다. 다섯 번째에는 어둠이 좁혀지고 35개가 차례로 정면을 봅니다. “이번엔 너를 셀게.”가 한 번 가까이 들립니다.
- 방해 없이 열둘까지 세면 짚신이 문틈으로 끌려갑니다. 두 결말 모두 끝나면 다음 관객을 위해 장면이 돌아옵니다.

## 실제 체와 어레미

경기도박물관의 야광귀 특별전 자료에 실린 국립민속박물관 소장 체는 얇은 나무를 굽혀 만든 원형 몸통과 바닥의 고운 망이 보입니다. 테의 이음에는 꿰맨 자국이 있습니다. 같은 박물관의 얼맹이는 가장자리가 낮고 대오리나 싸리를 엮은 성긴 망을 쓴 곡물 도구입니다. 소장품의 표기 치수는 지름 53, 높이 8입니다. [경기도박물관 〈신발귀신 야광귀〉](https://ggc.ggcf.kr/p/5be564578181b22cac08163f) · [국립민속박물관 소장 〈얼맹이〉](https://artsandculture.google.com/asset/sieve-unknown/VAGIQPfrd7EIHg?hl=ko)

민속 자료에는 집의 기둥이나 벽에 어레미 또는 체를 걸었다는 사례가 있습니다. 여러 형태의 생활 도구가 쓰였으며, 이번 장면은 얼맹이의 테와 가는 엮음을 살려 새로 제작했습니다. 체의 구멍을 눈으로 읽은 민속학자의 해석도 기록되어 있습니다. 실제로 눈이 나타나는 장면은 전시 연출입니다. [한국민속대백과사전 〈어레미〉](https://folkency.nfm.go.kr/topic/%EC%96%B4%EB%A0%88%EB%AF%B8) · [〈야광귀쫓기〉](https://folkency.nfm.go.kr/topic/detail/4471)

## 설치와 실행

Windows 전시 PC, Chrome 또는 Edge, 1920×1080 화면이나 프로젝터, 마이크 한 대, 스테레오 스피커나 앰프를 준비합니다. 출력과 입력 장치를 Windows에서 선택한 뒤 다음 순서로 시작합니다.

1. 저장소 루트나 제공받은 ZIP을 푼 폴더에서 `node tools/serve.mjs`를 실행합니다. 로컬 실행에는 Node.js가 필요합니다.
2. Chrome 또는 Edge에서 [로컬 야광귀](http://127.0.0.1:4387/ghost-exhibitions/works/yagwanggwi/)를 엽니다.
3. **전시 시작**을 누르고 마이크 권한을 허용합니다. 전체 화면이 제한된 브라우저에서는 F11을 사용합니다.
4. 마이크가 없으면 **Space**로 손뼉을 대신합니다. 시작 화면에서도 Space로 키보드 시연을 시작할 수 있습니다.

공개 전시는 브라우저에서 바로 실행할 수 있습니다. 로컬 HTTP는 loopback 주소를 사용하고 배포본은 Pages HTTPS를 사용합니다. [귀신 7종 통합 전시](https://jinwoon-bot.github.io/ghost-exhibitions/) · [야광귀 바로 열기](https://jinwoon-bot.github.io/ghost-exhibitions/works/yagwanggwi/)

캔버스와 배경은 원래 구도를 유지하며 화면에 맞춥니다. 좁은 화면에서는 남는 공간에 검은 여백을 둡니다. 앱을 실행할 때 서버는 정적 파일만 전달합니다. 외부 CDN, 실시간 생성 모델, API 키, 웹캠은 필요하지 않습니다.

## 운영실

| 조작 | 기능 |
| --- | --- |
| D | 운영실 열기와 닫기 |
| F | 전체 화면 전환 |
| Space | 박수와 같은 입력 |
| 입력 장치, 입력 레벨 | 마이크 선택, 권한 상태, 레벨, 감지 횟수, 기준 소음 확인 |
| 소음 재측정 | 약 1.15초간 현재 환경을 기준으로 재설정 |
| 박수 감도, 중복 방지 | 작은 박수 반응과 같은 박수의 중복 집계 조정 |
| 연출 | 숫자, 누적 횟수, 눈 단계 확인, 단계별 임계값 수정, 강제 클라이맥스·도난·초기화 |
| 음향 | 전체, 귀신, 환경, 효과 음량과 음소거 |
| 전시 | 전체 화면, 커서 숨김, 안전 모드, 자동 초기화, 오류·성능 확인 |

마이크는 손뼉을 치는 위치에서 직접 소리를 받을 수 있도록 관객 방향에 둡니다. 스피커 정면을 피하고, 실제 전시 음량으로 환경을 만든 뒤 소음 기준을 재측정합니다. 평상시 대화, 한 번의 박수, 빠른 여러 박수를 각각 시험한 다음 감도와 중복 방지 간격을 조절합니다.

장치가 빠지거나 권한이 거부되면 작품은 계속 진행됩니다. 운영실에서 마이크를 다시 연결하거나 키보드 모드를 선택합니다. 다른 앱이 입력 장치를 점유하는 경우 해당 앱을 닫고 다시 연결합니다. 오디오가 일시 중지된 경우 운영실에서 **오디오 다시 켜기**를 누릅니다.

## 기술과 에셋

| 항목 | 구현 |
| --- | --- |
| 대문과 어레미 | 기존 대문에서 체 부분을 이미지 생성으로 다시 작업한 `gate-oremi.jpg` |
| 눈·눈꺼풀 | 이미지 생성 텍스처 `eye-sheet.jpg`. 각 눈의 시선, 밝기, 깜빡임, 등장 시간이 다릅니다. |
| 어레미 엮음 | 새 장면의 어두운 틈을 분리한 `weave-apertures.png`와 눈 위치 35곳을 지정한 `weave-eyes.json` |
| 짚신 | 이미지 생성으로 제작한 투명 `jipsin.png`. 원근 크기, 접지 그림자, 문턱 방향 이동을 Canvas에서 합성합니다. |
| 음성 | 한국어 숫자 12개와 마지막 대사 1개를 Supertone Supertonic 2 M3로 합성한 WAV입니다. 실제 배우 녹음은 포함되지 않습니다. |
| 공간 효과음 | 체 두드림, 손톱 긁힘, 숨, 나무, 발소리, 짚신 끌림, 밤 공간음, 저음을 `sound.mjs`가 원본 파형으로 합성합니다. |

한국어 WAV는 기계가 생성한 합성 음성입니다. 음성 모델은 제작 단계에서만 사용했으며 실행본에는 학습 모델이나 음성 생성 서비스가 포함되지 않습니다. 현장 캡션과 공개 소개에도 합성 음성임을 표기하세요. [Supertonic 2 모델 카드](https://huggingface.co/Supertone/supertonic-2) · [출력 및 사용 조건](https://huggingface.co/Supertone/supertonic-2/blob/main/LICENSE)

관객 마이크는 AudioWorklet에서 짧은 창의 레벨, 에너지 상승과 하강, 고역 및 저역 비율, 피크, 주변 기준을 계산하는 데만 사용됩니다. 원본 마이크 신호는 음향 출력으로 보내지 않으며 녹음하거나 전송하지 않습니다. 저장되는 값은 운영 설정뿐입니다.

음성·환경·효과 버스는 분리되어 있습니다. 숫자를 세는 목소리는 문 안쪽 방향의 대역과 짧은 반사음을 쓰고, 마지막 대사는 중앙의 건조한 음색으로 재생합니다. 음원 충돌을 막기 위해 새 대사와 박수 반응에서 현재 대사를 정리합니다. 압축기와 최대 출력 제한을 적용합니다. 제작 음원을 교체하려면 `assets/voice/manifest.json`에 같은 순서로 12개의 로컬 WAV 또는 MP3와 마지막 대사 파일을 지정합니다. 일부 파일이 비어 있으면 기기에 설치된 한국어 음성을 쓰고, 음성이 없는 기기에서는 효과음과 장면으로 진행합니다.

## 검증 기록

| 시험 | 확인한 결과 |
| --- | --- |
| 자동 상태 시험 | 최초 세기, 즉시 중단, 한 번의 박수 중복 배제, 하나 재시작, 단계별 누적, 두 결말, 자동 복귀와 운영자 정지 설정을 통과했습니다. |
| 합성 PCM | 소음, 저역 신호 및 지속 음성이 섞인 입력에서 서로 떨어진 박수 3회를 감지했습니다. 가까운 중복은 제외했고, 테스트 신호에서는 시작 56ms 이내에 판단했습니다. |
| 브라우저 AudioWorklet | 최초 공개판에서 가상 입력 8회 중 가까운 한 번을 제외한 7회가 상태 시스템에 도달했습니다. 인식 모듈은 어레미판에도 동일하게 사용됩니다. |
| 마이크 없음과 권한 거부 | 장치 없음 오류를 주입해 Space 안내를 확인했습니다. 브라우저 권한 거부 시뮬레이션에서 Space로 숫자를 끊고 1부터 다시 시작했습니다. |
| 브라우저 화면과 운영실 | 어레미판에서 1개, 4개, 9개, 16개를 확인했고, 다섯 번째 입력에서 35개가 나타났습니다. 1920×1080 시연에서 운영실의 60 FPS 표시를 확인했습니다. 이전 공개판에서 짚신 도난, 자동 복귀, 설정 복원과 세로 레이아웃을 확인했습니다. |
| 음향 | 브라우저에서 동봉 합성 WAV 13개 디코딩과 재생 가능한 Web Audio 상태를 확인했습니다. |
| 반복 운영 | 3시간 가상 시간 동안 장면 359회 복귀와 이벤트 수 상한을 확인했습니다. 실제 브라우저와 장치의 장시간 측정은 현장 검증이 남았습니다. |
| 정적 검사 | 기존 GitHub Pages 검사 도구와 실제 localhost의 중첩 경로에서 정적 파일을 확인했습니다. 브라우저 시연에서 확인한 콘솔 오류는 없었습니다. |

실물 마이크로 관객의 박수를 수음한 테스트, 전시용 스피커로 최종 대사 발음과 음량을 들은 테스트, 전시장 PC의 전체 화면과 장시간 실운영은 현장 검증이 남아 있습니다. 이번 내장 브라우저는 전체 화면 권한을 제한했습니다. 현장에서는 화면 검은 영역이 뭉개지지 않는지, 마이크가 스피커를 박수로 오인하지 않는지, 실제 밝기와 음량에서 양쪽 결말이 읽히는지 확인하세요.
